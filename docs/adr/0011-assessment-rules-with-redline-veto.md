# 0011. 考核评分：规则引擎 + 红线一票否决

- 状态：Accepted
- 日期：2026-10-30
- 影响范围：`api/app/qa/rules.py`、`api/app/qa/service.py`

## 背景

考核类功能的难点不在算分，在**服众**。同一条会话，主管看是 80 分，坐席看是"我已经尽力了"，如果系统只给一个数字，这场对话就没法进行。

更麻烦的是模型评分。让 LLM 读一遍会话打个分很容易，但它给不出稳定、可复现、可解释的分数：同一句话换个说法，分数从 72 变成 78；问它"为什么扣了 8 分"，它会给一段听起来合理但每次都不一样的理由。考核结果要用来谈话、发奖金，这种分数不能用。

## 决策

**规则引擎，不是模型评分。** 五条规则，权重之和 100，每条都是纯函数：

| 项 | 权重 | 判据 |
|---|---|---|
| 响应完整性 | 30 | 每条客户发言之后是否都有坐席回复 |
| 首响时效 | 20 | 首条回复延迟 ≤60 秒满分，≥300 秒 0 分，中间线性 |
| 需求覆盖 | 25 | 客户问的每一类问题（价格/库存/物流/用法/售后），回复是否覆盖 |
| 推进动作 | 15 | 是否给出下一步（链接/优惠/下单/跟进时间） |
| 礼貌用语 | 10 | 开场问候 + 结束致谢各 5 分 |

**每个扣分都必须带证据。** 每条规则输出 `evidence`：第几句、原话片段、为什么引用它。报告页可以直接把"第 3 句（坐席）"和原文对上。没有证据的扣分在考核场景里是不合格的。

**红线一票否决，不参与加权。** 绝对化承诺（"百分百""保证""绝对"）、私下交易（"加微信""转账"）、失礼推诿，命中即总分归零并单独标记。做成"扣 30 分"是错的：扣完还剩 70 分，会挤进 B 级，而这三类事的性质是"不该发生"，不是"这轮做得不够好"。

**红线只看坐席说的话。** 客户骂人不算坐席的错。

**不猜。** 缺消息时间戳时，首响时效判 0 并在 `detail` 里写明"无法计算（不猜）"，而不是假设一个大概的延迟；会话里没有客户发言时，完整性与需求覆盖都判 0 并说明。编出来的分数比低分更糟。

## 后果

- 得到：分数可复现。同样的会话文本任何机器任何时候算出来都一样，`rule_version` 一起落库，规则改了能看出是哪一版算的。
- 得到：报告能落到一句话。`weakest` 取"失分最多的一项"（不是得分最低的一项——满分 10 的 0 分只丢了 10 分），配它自己的 `advice`。
- 付出：规则覆盖面有限，识别不了"态度很好但答错了"这类需要理解的判断。这是有意的取舍：宁可漏判也不要给出无法解释的分数。
- 付出：`INTENTS` 与 `ACTION_PHRASES` 是手工维护的短表。新增业务话术（比如"预约"）要登记，否则那一类推进动作会被判 0。

## 一次真实的返工

`需求覆盖` 最初实现为"客户原话的关键词有没有出现在回复里"（复用 RAG 的 bigram 分词）。实测第一条就错了：

```
客户：这个低糖饼干还有货吗，多少钱
坐席：您好，有的，29.9 元一盒，可以帮您留货，稍后发链接给您
```

人看着完全答到了，但字面交集是 0——回复没有重复商品名。规则判 0 分，整条会话从 100 掉到 75。

改成"问题类型覆盖"后判据变成"客户问价格，回复里有没有报价"，既可解释又不会因为换个说法就崩。这件事的教训写进了 ADR 0008 的同一条原则：**判断要落在语义类别上，不要落在字面重合上**。

## 第二次返工：红线也要防字面重合（规则 1.0.1）

同一条原则在红线上又踩了一次，而且后果更重。

P01 的会话流入 P09 之后，AI 助手 11 条会话里有 3 条被判红线、总分归零。查证据，命中的是 `rudeness` 的「滚」，而原句是运营复盘里的「第二版主图**回滚**」。`"滚" in text` 判真，一票否决。

3/11 条会话作废，均分被从 85.5 拉到 60.9。

红线是一票否决，**误判的代价天然不对称**：漏判是"这一轮没抓住"，误判是"把一条正常会话定性成辱骂"——报告里会赫然写着「失礼或推诿」，看的人第一反应是系统坏了，第二反应是不再信任这个分数。

修法不是删关键词（那样真骂人也报不出来），而是两层收口：

1. 裸「滚」这种单字不再作为关键词，换成 `滚开 / 滚蛋 / 滚出去 / 滚远点`——骂人的是这些，不是那个字。
2. 更通用的兜底：`REDLINE_BENIGN_COMPOUNDS` 登记"命中词被更长的正常词吞掉"的情形，`_find_redline_phrase` 跳过被覆盖的那次命中。顺带挡住两个同类坑：`保证 → 保证金`、`无理由 → 天无理由`（「7 天无理由退换」是法定权利，FAQ 的标准答案里就写着，误判的话客服每答一次退货政策就把自己打成 0 分）。

`RULE_VERSION` 升到 `1.0.1`。旧分数保留原版本号，`rescore` 才会改写——同一次数据在 1.0.0 和 1.0.1 下的差别是可见的，这正是版本号存在的意义。
