# 0013. 客服三轨道分流：先判该不该答，再判答得出来答不出来

- 状态：Accepted
- 日期：2026-10-30
- 影响范围：`api/app/cs/intents.py`、`api/app/cs/answer.py`、`api/app/cs/service.py`

## 背景

电商客服的提问不是一个类型的问题。同一句「你们什么时候发货」，背后可能是三种完全不同的诉求：

1. 客户想知道规则（FAQ 能答，且必须答得和详情页一字不差）
2. 客户想知道事实（库存、活动、物流轨迹——知识在运营资料里，得检索）
3. 客户要的不是答案，是人（投诉、维权、情绪失控）

单一路径的问答系统在第三种上会出事：客户说「我要投诉，你们发的是假货」，系统很认真地检索了"假货"相关资料，回了一段关于品质管控的说明。这段话在语义上没错，在人看来是灾难。

第二个问题更隐蔽：**检索永远会返回 top-k**。哪怕知识库里完全没相关内容，它也会挑一条最接近的。把这条件直接当答案，等于系统永远不承认自己不知道。

## 决策

**三轨道加一条兜底，判轨道在取依据之前。**

```
转人工  → 命中投诉/维权、明确要求人工、强烈负面情绪、要求升级
FAQ     → 命中内置确定性条目
检索    → 混合检索，命中够格就答
拒答    → 都不满足，承认查不到并给转人工入口
```

轨道顺序是有讲究的，从「人的诉求」到「知识」到「不确定性」，越靠前越不该被后面的机制覆盖。

### 转人工先判

`_HANDOFF_RULES` 四条按优先级排列：`complaint`（投诉/维权）→ `explicit_request`（明确要求人工）→ `negative_emotion`（强烈负面）→ `escalation`（要求升级处理）。命中第一条即返回，不同时命中多条——工单上只需要一个理由，多个理由会让值班的人去猜该按哪条处理。

优先级不是随手排的。一条消息同时含"投诉"和"转人工"时，`complaint` 更该被记录：它决定了工单的 `priority`（`high` 而不是 `normal`），也决定了后续复盘时这条会话被归到哪一类问题。

### 拒答线取实测分数

`VECTOR_FLOOR = 0.36` 不是估的。用仓库里两篇运营资料实际跑出 top1 原始分数：

| 问题 | 词法分 | 向量相似度 | 实际该不该答 |
|---|---|---|---|
| 竞品价格怎么应对 | 2.1995 | 0.6044 | 该 |
| 低糖饼干卖给谁 | 0.8979 | 0.7030 | 该 |
| 缺货要不要紧 | — | 0.4338 | 该 |
| 素材哪一版更好 | 1.9199 | 0.3882 | 该 |
| 快递几天能到 | — | 0.3378 | 不该（FAQ 里答） |
| 我要退货怎么操作 | — | 0.3234 | 不该（FAQ 里答） |
| 你是谁开发的 | — | 0.2590 | 不该 |
| 今天天气怎么样 | — | 0.2152 | 不该 |

相关最低 0.3882、无关最高 0.3378，中间只有 0.05 的空隙，阈值只能取中点 **0.36**。

这张表和阈值写在同一个文件里（`answer.py` 的模块 docstring），因为它们必须一起维护：**改阈值的人应该先重跑一遍这张表**。语料变了，这个空隙就会移动。

`pick_from_hits` 的两条判据不一样，这里刻意不对称：

- **词法命中不设分数阈值。** BM25 的分数量纲随语料长度变化，跨资料不可比；只要 `matched_terms` 非空，说明有实词字面重合，这就是依据。
- **纯向量命中必须过 `VECTOR_FLOOR`。** 向量相似度有稳定量纲（余弦），阈值可以跨语料沿用。

拒答时不能说"我不知道"就完事。回复里必须带一句**最接近的那条相似度是多少**——`（最接近的一条相似度 0.27，低于 0.36）`。这句是给客户的解释，更是给运维的线索：相似度只有 0.21 说明知识库里真的没有；如果长期在 0.35 附近，说明阈值或语料该调了。

## 后果

- 得到：拒答成为正常结果而不是故障。实测五条消息里，一条「你们公司什么时候上市」稳定拒答，其余四条各走各的轨道。
- 得到：投诉类的问题不会掉进检索里被"善意地敷衍"。
- 付出：`_HANDOFF_RULES` 和 `FAQ_ITEMS` 都是手工维护的短表。新业务话术要登记，否则会被判成检索或拒答。这是刻意的：能直答的必须是确定的，不确定的宁可走检索。
- 付出：轨道判定只看**当前这一句**，不看上下文。多轮追问（"那这个呢？"）识别不了，会落到拒答。这是下一步要补的，不是现在能糊过去的。
- 重新考虑的条件：知识库语料规模上来之后，0.36 需要重标定；如果加入 rerank 模型，分数分布会整体移动，`VECTOR_FLOOR` 必须重新实测。
